# INSTRUCCIONES Y GUÍA DE DESARROLLO - SISTEMA DE ENCUESTAS DE SATISFACCIÓN (MVP v1.3)

## 1. Propósito

Este documento proporciona instrucciones detalladas y pasos específicos para los desarrolladores que implementarán el MVP del Sistema de Encuestas de Satisfacción, siguiendo la especificación técnica v1.3 y las reglas definidas en `REGLAS_PROYECTO.md`. El objetivo es minimizar la ambigüedad y asegurar una implementación consistente.

**NOTA:** Antes de comenzar, asegúrate de haber leído y comprendido completamente los archivos `CONTEXTO_ALCANCE.md` y `REGLAS_PROYECTO.md`.

## 2. Configuración Inicial del Entorno

1.  **Crear Proyecto Supabase:**
    *   Accede a [supabase.com](https://supabase.com/) y crea un nuevo proyecto.
    *   Selecciona una región cercana a tus usuarios/desarrolladores.
    *   Guarda de forma segura la URL del proyecto, la clave `anon` (pública) y la clave `service_role` (secreta). **NUNCA** expongas la clave `service_role` en el código del frontend.
    *   (Opcional) Habilita extensiones si es necesario (ej: `uuid-ossp`, aunque Supabase suele manejar UUIDs por defecto).
2.  **Configurar Repositorio Git:**
    *   Inicializa un repositorio Git.
    *   Crea las ramas `main` y `develop`. Trabaja siempre sobre ramas `feature/*` creadas a partir de `develop`.
    *   Añade los archivos de documentación (`CONTEXTO_ALCANCE.md`, `REGLAS_PROYECTO.md`, `INSTRUCCIONES_DESARROLLO.md`) a la raíz y haz el commit inicial en `develop`.
3.  **Configurar Proyecto Frontend (React + Vite):**
    *   Utiliza Vite para crear un nuevo proyecto React con TypeScript: `pnpm create vite nombre-proyecto --template react-ts` (o `npm`/`yarn`).
    *   Instala las dependencias necesarias: `pnpm install supabase-js react-router-dom tailwindcss postcss autoprefixer @heroicons/react` (u otras librerías de iconos/UI si se eligen).
    *   Configura Tailwind CSS siguiendo su documentación oficial para Vite.
    *   Configura ESLint y Prettier según lo definido en `REGLAS_PROYECTO.md`.
    *   Crea variables de entorno (`.env`) para las claves públicas de Supabase (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`). Asegúrate de incluir `.env` en tu `.gitignore`.
4.  **Configurar Entorno Supabase CLI (Local):**
    *   Instala la [Supabase CLI](https://supabase.com/docs/guides/cli).
    *   Vincula tu proyecto local al proyecto Supabase remoto: `supabase login`, `supabase link --project-ref TU_ID_PROYECTO`.
    *   Inicializa el entorno local (opcional pero recomendado para desarrollo y migraciones): `supabase init`.

## 3. Implementación de la Base de Datos

1.  **Crear Migraciones:** Utiliza la Supabase CLI para gestionar las migraciones de la base de datos.
    *   Crea una nueva migración: `supabase migration new nombre_migracion` (ej: `create_initial_schema`).
    *   Edita el archivo SQL generado en la carpeta `supabase/migrations`.
    *   Copia y pega el esquema SQL detallado en la Sección 5 del archivo `REGLAS_PROYECTO.md` (versión v1.3 con comentarios en español) dentro del archivo de migración.
    *   **Importante:** Asegúrate de que los tipos de datos sean compatibles con Supabase/PostgreSQL (ej: `SERIAL` se traduce a `BIGINT GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMPTZ` es correcto, `UUID` es el tipo por defecto para IDs si lo prefieres). Revisa la sintaxis de `FOREIGN KEY` y `UNIQUE constraints`.
2.  **Aplicar Migraciones (Desarrollo Local):** `supabase db reset` (para empezar limpio) o `supabase migration up`.
3.  **Aplicar Migraciones (Producción/Remoto):** `supabase migration up --linked` (o gestionado a través de CI/CD).
4.  **Configurar Políticas RLS (Row Level Security):**
    *   **¡CRÍTICO PARA LA SEGURIDAD!** Define políticas DETALLADAS para CADA tabla.
    *   Usa el editor de políticas de Supabase o créalas en archivos SQL y aplícalas con la CLI.
    *   **Ejemplos de Políticas:**
        *   `surveys`: `anon` y `authenticated` pueden `SELECT` si `is_active = true`. Solo `authenticated` con rol `admin` (requiere configurar roles o usar perfiles) pueden `INSERT`, `UPDATE`, `DELETE`.
        *   `survey_responses`: `anon` o `authenticated` pueden `INSERT`. Solo el usuario que creó la respuesta (necesita `user_id` o un token/sesión seguro) o un `admin` pueden `SELECT` o `UPDATE`. `DELETE` solo para `admin`.
        *   `answers`: Similar a `survey_responses`, basado en el `response_id`.
        *   `product_codes`: `SELECT` restringido. `UPDATE` (para marcar como `used`) solo permitido a través de la función/EF de finalización. `INSERT` solo por la EF de generación. `DELETE` solo `admin`.
        *   Tablas Admin (`code_batches`, `survey_code_batches`, etc.): Acceso completo solo para `admin`.
    *   **Habilita RLS para cada tabla** una vez definidas las políticas.

## 4. Desarrollo de Edge Functions (TypeScript)

1.  **Crear Funciones:** Usa la Supabase CLI: `supabase functions new nombre-funcion`.
2.  **Estructura:** Organiza el código de cada función dentro de su carpeta correspondiente en `supabase/functions`.
3.  **Implementar Lógica:** Escribe el código TypeScript para cada función requerida (ver Sección 6 de `REGLAS_PROYECTO.md` para las responsabilidades detalladas):
    *   `validate-product-code`
    *   `generate-product-codes`
    *   `finalize-survey-response` (puede invocar una función DB vía RPC)
    *   `export-responses-csv`
4.  **Cliente Supabase en Funciones:** Importa y utiliza `supabase-js` dentro de las funciones para interactuar con la base de datos. Usa la `service_role` key (cargada desde secretos/variables de entorno de la función) para operaciones que requieren permisos elevados, o pasa el token de autorización del usuario si la función debe operar con sus permisos.
5.  **Tipado:** Define interfaces claras (ej: `RequestData`, `ResponseData`) para los datos de entrada y salida de cada función.
6.  **Manejo de Errores:** Implementa bloques `try...catch` y devuelve respuestas de error consistentes (ej: `new Response(JSON.stringify({ error: 'Mensaje de error' }), { status: 400 })`).
7.  **CORS:** Configura las cabeceras CORS adecuadas en las respuestas de las funciones para permitir llamadas desde tu dominio frontend.
8.  **Despliegue:** `supabase functions deploy nombre-funcion --project-ref TU_ID_PROYECTO`.

## 5. Desarrollo Frontend (React)

1.  **Estructura del Proyecto:** Organiza el código en carpetas lógicas (ej: `src/components`, `src/pages`, `src/hooks`, `src/services`, `src/contexts`, `src/types`).
2.  **Cliente Supabase:** Crea una instancia única del cliente Supabase (`createClient`) y provéela a la aplicación (ej: mediante un Context).
3.  **Routing:** Usa `react-router-dom` para definir las rutas de la aplicación (pública y admin). Implementa rutas protegidas para el panel de administración.
4.  **Autenticación Admin:** Implementa el flujo de login/logout usando `supabase.auth.signInWithPassword()`, `supabase.auth.signOut()`, y `supabase.auth.onAuthStateChange()` para gestionar la sesión del usuario. Guarda la información del usuario en un Context global.
5.  **Componentes UI:** Desarrolla los componentes React necesarios para cada pantalla/funcionalidad descrita en el alcance, utilizando Tailwind CSS para los estilos.
6.  **Llamadas a Supabase:**
    *   Para CRUD básico (protegido por RLS), usa los métodos de `supabase-js` (ej: `supabase.from('surveys').select('*')`).
    *   Para lógica compleja o endpoints personalizados, invoca las Edge Functions: `supabase.functions.invoke('nombre-funcion', { body: { ... } })`.
7.  **Gestión de Estado:** Usa estado local (`useState`, `useReducer`) y React Context para estado global simple.
8.  **Formularios:** Implementa formularios controlados con manejo de estado, validación y feedback al usuario. Para formularios complejos (creación de encuestas), considera librerías como `react-hook-form`.
9.  **Guardado de Progreso (Cliente):**
    *   Utiliza `localStorage` para guardar el estado actual de la respuesta (sección actual, respuestas dadas).
    *   Al cargar la encuesta, verifica `localStorage` y restaura el estado si existe.
    *   Al navegar o modificar respuestas, actualiza `localStorage` y realiza `UPSERT` en la tabla `answers` vía `supabase-js`.
10. **Manejo de Errores:** Muestra mensajes de error claros al usuario si fallan las llamadas a Supabase.

## 6. Tareas Específicas (Ejemplos Detallados)

*   **Generar Códigos (`generate-product-codes` EF):**
    *   Recibe `batch_id`, `quantity`, etc.
    *   Dentro de un bucle `quantity` veces:
        *   Genera una cadena aleatoria única (usando librerías criptográficas si es posible).
        *   Verifica si ya existe en `product_codes` (bucle `do...while` hasta encontrar uno único).
        *   Añade el objeto `{ batch_id: ..., code_value: ... }` a un array.
    *   Realiza una única llamada `supabase.from('product_codes').insert(arrayDeCodigos)`.
    *   Maneja errores (ej: si `batch_id` no existe).
*   **Finalizar Encuesta (`finalize-survey-response` EF / DB Function):**
    *   Recibe `response_id`.
    *   **PASO CLAVE: Transacción.** La forma más segura es definir una función `plpgsql` en la BD (`FUNCTION finalize_survey(response_id_in INT) RETURNS JSON`) que haga los UPDATES/INSERTs necesarios (response, discount_code, product_code) de forma atómica. La Edge Function simplemente llamaría a esta función DB vía RPC: `supabase.rpc('finalize_survey', { response_id_in: response_id })`.
    *   *Dentro de la función DB o EF:* Calcular descuento, generar código único, calcular fecha expiración, realizar las operaciones de BD.
    *   Devolver el resultado (éxito/fracaso, código generado, etc.).
*   **Exportar CSV (`export-responses-csv` EF):**
    *   Construir la consulta SQL con JOINs necesarios para obtener todos los campos requeridos para el CSV.
    *   Ejecutar la consulta: `supabase.rpc('nombre_funcion_sql_reporte', { filtros })` o construirla dinámicamente si es necesario (cuidado con SQL injection si se usan filtros dinámicos).
    *   Recibir los datos JSON.
    *   Usar una librería (ej: `papaparse` si se usa Node.js compatible, o lógica manual/librería Deno) para convertir el JSON a formato CSV.
    *   Devolver la respuesta con `Content-Type: text/csv`.

## 7. Consideraciones Finales

*   **Seguridad:** Revisa constantemente las políticas RLS y la lógica de las Edge Functions para evitar vulnerabilidades. Asegúrate de que las claves secretas estén seguras.
*   **Rendimiento:** Monitoriza el rendimiento de las consultas y funciones. Añade índices a la base de datos donde sea necesario.
*   **Iteración:** Este es un MVP. Enfócate en entregar las funcionalidades clave definidas. Documenta ideas o mejoras para futuras versiones.
*   **Comunicación:** Mantén una comunicación fluida con el equipo y el arquitecto/líder del proyecto si surgen dudas o bloqueos.
